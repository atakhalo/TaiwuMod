## 请求类型详解

> **大结果处理**：当响应数据超过 1000 个字符时，自动写入独立的 `result_{requestId}.json` 文件，`result.json` 中只保留 `requestId`、`success`、`hasLongResult: true`、`longResultFile` 等简要字段。外部程序根据 `longResultFile` 读取完整结果。

### 1. 场景层级查询 `scene_hierarchy`

查询 Unity 场景中的 GameObject 层级结构。

**请求：**
```json
{
    "requestId": "scene_001",
    "type": "scene_hierarchy",
    "params": {
        "rootType": "all_canvases"
    }
}
```

| 参数       | 类型   | 必填                    | 说明                                                              |
| ---------- | ------ | ----------------------- | ----------------------------------------------------------------- |
| `rootType` | string | 否                      | `"all_canvases"`（列出所有Canvas，默认）或 `"path"`（按路径查询） |
| `path`     | string | 当rootType="path"时必填 | 路径，如 `"Canvas/CharacterMenu/..."`                             |
| `attach`   | array  | 否                      | 附加链（注意：scene_hierarchy 无原始对象，attach 不生效）         |

**响应示例：**
```json
{
    "requestId": "scene_001",
    "success": true,
    "data": [
        {
            "name": "Canvas",
            "active": true,
            "path": "Canvas",
            "components": ["Canvas", "CanvasScaler", "GraphicRaycaster"],
            "localPosition": {"x": 0, "y": 0, "z": 0},
            "childCount": 5,
            "children": [
                {
                    "name": "MainMenu",
                    "active": true,
                    "path": "Canvas/MainMenu",
                    "components": ["RectTransform", "Image", "Button"],
                    "localPosition": {"x": 0, "y": 100, "z": 0},
                    "childCount": 3,
                    "children": [ ... ]
                }
            ]
        }
    ]
}
```

> 层级递归深度默认为 5 层，超出部分以 `childrenTruncated: true` 标记。

### 4. 后端反射链 `back_code`

通过完整类名作为入口，依次执行 `chain`（字段/方法/属性）进行反射调用，支持 `attach` 在主结果上继续执行附加链。
请求走后端路由，由 `BackendDataService` 处理。

**请求：**
```json
{
    "requestId": "data_001",
    "type": "back_code",
    "params": {
        "entry": { "name": "GameData.Domains.DomainManager" },
        "chain": [
            { "step": "field", "name": "Character" },
            { "step": "method", "name": "GetElement_Objects", "argTypes": ["System.Int32"], "args": [10001] },
            { "step": "method", "name": "GetFullName" },
            { "step": "field", "name": "Surname" }
        ],
        "resultDepth": 3
    }
}
```

**参数：**

| 参数 | 类型 | 必填 | 说明 |
|:----|:----|:----|:-----|
| `entry` | object | 是 | 起点，`{ "name": "完整类名" }` |
| `chain` | array | 否 | 执行链，每项见下方 |
| `resultDepth` | int | 否 | 结果序列化深度，默认 3 |
| `attach` | array | 否 | 附加链，格式与主链相同 |

**chain 每项格式：**

| 字段 | 类型 | 必填 | 说明 |
|:----|:----|:----|:-----|
| `step` | string | 是 | `"method"` / `"field"` / `"property"` |
| `name` | string | 是 | 成员名（方法名支持 `Method<Type>` 泛型语法） |
| `stepType` | string | 否 | 结果类型全名（文档用） |
| `argTypes` | string[] | 仅 method | 参数类型全名数组，用于重载解析 |
| `args` | array | 仅 method | 参数值数组 |
| `codeArgs` | int[] | 否 | 参数注入标记，与 `args` 索引一一对应，值为 `1` 时表示对应 args 元素为 code 子请求（见下方说明） |

> **`codeArgs` 说明**：当方法需要复杂对象参数时，可将对应 args 元素写为一个完整的 code 请求（无 `requestId`），并在 `codeArgs` 的同索引位置标记为 `1`。系统会先递归执行该子请求，将结果作为参数传入目标方法。子请求的 chain 中同样可嵌套 `codeArgs`，实现递归注入。

**执行流程：**
```
entry (类名) → 获取 Type/Instance
  → chain[0] (field/property/method) → 对象 A
    → chain[1] (field/property/method) → 对象 B
      → ... → 序列化结果 (resultDepth 层)
```

**进阶特性：**

- **泛型方法调用** — 方法名支持 `<类型名>` 语法，如 `"GetComponent<RectTransform>"` 自动解析泛型
- **枚举参数自动转换** — 方法参数为 enum 时直接传 `int`，自动 `Enum.ToObject` 转换
- **数字类型兼容** — `int`↔`sbyte`↔`short`↔`long`↔`float`↔`double` 自动转换

**使用示例：**

查询太吾的当前日期：
```json
{
    "type": "back_code",
    "params": {
        "entry": { "name": "GameData.Domains.DomainManager" },
        "chain": [
            { "step": "field", "name": "World" },
            { "step": "method", "name": "GetCurrDate" }
        ]
    }
}
```

读角色姓名（链式+字段）：
```json
{
    "type": "back_code",
    "params": {
        "entry": { "name": "GameData.Domains.DomainManager" },
        "chain": [
            { "step": "field", "name": "Character" },
            { "step": "method", "name": "GetNameRelatedData", "argTypes": ["System.Int32"], "args": [10001] },
            { "step": "field", "name": "FullName" }
        ]
    }
}
```

枚举参数示例：
```json
{
    "type": "back_code",
    "params": {
        "entry": { "name": "GameData.Domains.DomainManager" },
        "chain": [
            { "step": "field", "name": "Organization" },
            { "step": "method", "name": "GetSettlementIdByOrgTemplateId", "argTypes": ["System.SByte"], "args": [4] }
        ]
    }
}
```

**codeArgs 注入示例：**

当方法需要复杂对象作为参数时，可用 `codeArgs` 将 args 中对应索引标记为子请求，系统自动执行子请求并将结果注入为参数。

```json
{
    "type": "back_code",
    "params": {
        "entry": { "name": "GameData.Domains.Character.CharacterDomain" },
        "chain": [
            {
                "step": "method",
                "name": "SomeMethodWithCharacterParam",
                "argTypes": ["GameData.Domains.Character.Character"],
                "args": [
                    {
                        "type": "back_code",
                        "params": {
                            "entry": { "name": "GameData.Domains.DomainManager" },
                            "chain": [
                                { "step": "field", "name": "Character" },
                                { "step": "method", "name": "GetElement_Objects", "argTypes": ["System.Int32"], "args": [10001] }
                            ]
                        }
                    }
                ],
                "codeArgs": [1]
            }
        ]
    }
}
```

> `codeArgs: [1]` 表示 args[0] 是子请求（数组长度与 args 对应，索引 0 标记为 1）。系统先执行子请求得到 `Character` 对象，再作为第一个参数调用方法。

**递归注入：** 子请求的 chain step 中同样可嵌套 `codeArgs`，实现深层递归。注意子请求类型须与父请求一致（`back_code` 内层必须也是 `back_code`；`front_code` 同理），不支持跨类型注入。

**可用 DomainManager 入口字段：**

`GameData.Domains.DomainManager` 上的静态字段（可直接用 `"step": "field"` 访问）：

| 字段名 | 类型 | 说明 |
|:------|:----|:-----|
| `World` | WorldDomain | 世界数据 |
| `Map` | MapDomain | 地图数据 |
| `Organization` | OrganizationDomain | 组织数据 |
| `Character` | CharacterDomain | 角色数据 |
| `Taiwu` | TaiwuDomain | 太吾数据 |
| `Item` | ItemDomain | 物品数据 |
| `CombatSkill` | CombatSkillDomain | 战斗技能 |
| `Combat` | CombatDomain | 战斗数据 |
| `Building` | BuildingDomain | 建筑数据 |
| `Adventure` | AdventureDomain | 冒险数据 |
| `Merchant` | MerchantDomain | 商人数据 |
| `Extra` | ExtraDomain | 扩展数据 |

### 9. 前端反射链 `front_code`

通过完整类名作为入口，依次执行 `chain` 进行前端 Unity 对象上的反射调用。
请求走前端路由，由主线程协程处理。

**请求示例 — 查询特定字段：**
```json
{
    "requestId": "fe_001",
    "type": "front_code",
    "params": {
        "entry": { "name": "BasicGameData" },
        "chain": [
            { "step": "field", "name": "TaiwuCharId" }
        ]
    }
}
```

**请求示例 — 查询所有字段（不传 chain）：**
```json
{
    "requestId": "fe_002",
    "type": "front_code",
    "params": {
        "entry": { "name": "BasicGameData" },
        "resultDepth": 2
    }
}
```

**请求示例 — 链式方法 + 读字段：**
```json
{
    "requestId": "fe_003",
    "type": "front_code",
    "params": {
        "entry": { "name": "CharacterMonitorModel" },
        "chain": [
            { "step": "method", "name": "GetMonitorItem<CharacterDataMonitor.DetailInfoMonitor>", "argTypes": ["System.Int32", "System.Boolean"], "args": [7059, false] },
            { "step": "field", "name": "Attraction" }
        ],
        "resultDepth": 2
    }
}
```

**参数：**

| 参数 | 类型 | 必填 | 说明 |
|:----|:----|:----|:-----|
| `entry` | object | 是 | 起点，`{ "name": "完整类名" }` |
| `chain` | array | 否 | 执行链，格式与 `back_code` 相同 |
| `resultDepth` | int | 否 | 结果序列化深度，默认 3 |
| `attach` | array | 否 | 附加链 |

**entry 解析规则：**

1. 在所有已加载程序集中搜索类名
2. 尝试获取静态 `Instance` 属性/字段
3. 尝试调用 `getInstance()` 方法（SingletonObject 模式）
4. 否则返回 Type 本身（静态成员访问）

**可用类型示例：**

| 类型名 | 说明 | 获取方式 |
|:------|:-----|:---------|
| `BasicGameData` | 基础游戏数据（太吾ID、日期等） | SingletonObject.getInstance |
| `CharacterMonitorModel` | 角色监控（同道、魅力等） | SingletonObject.getInstance |
| `UnityEngine.GameObject` | Unity 场景对象 | 静态方法（`Find`） |

### 10. 模拟指针点击 `simulate_click`

通过 Unity EventSystem 创建真实的 `PointerEventData`，使用 `ExecuteEvents.Execute` 触发目标 GameObject 上的 `IPointerClickHandler`。行为和真实鼠标点击完全一致。

**请求：**
```json
{
    "requestId": "click_001",
    "type": "simulate_click",
    "params": {
        "gameObjectPath": "Camera_UIRoot/Canvas/..."
    }
}
```

| 参数 | 类型 | 必填 | 说明 |
|:----|:----|:----|:-----|
| `gameObjectPath` | string | 是 | 目标物体的完整路径 |

**响应示例（成功）：**
```json
{
    "requestId": "click_001",
    "success": true,
    "data": {
        "success": true,
        "target": "RecordInfo_1",
        "executed": 2
    }
}
```

`executed` 表示触发了几个 `IPointerClickHandler` 组件。

**响应示例（失败）：**
```json
{
    "requestId": "click_001",
    "success": false,
    "error": "在 RecordInfo_1 上找不到 IPointerClickHandler"
}
```

> **用途：** 主要用于存档选中——存档槽位上的 `PointClickBridge` 实现了 `IPointerClickHandler`，`simulate_click` 能正确触发完整的选中逻辑（更新内部索引、激活 BtnHolder、设置 Toggle 状态）。

### 11. 商店筛选购买 `shop_buy_filtered`

通过后端 Exchange.SelectTargetItem 直接筛选商品加入交换列表，不走 UI 模拟点击。请求走前端路由，由主线程协程处理。

**请求：**
```json
{
    "requestId": "shop_001",
    "type": "shop_buy_filtered",
    "params": {
        "filters": [
            {"name": "香菇", "amount": 2},
            {"itemType": 5, "pricePercent": -1}
        ]
    }
}
```

| 参数 | 类型 | 必填 | 说明 |
|:----|:----|:----|:-----|
| `filters` | array | 是 | 筛选条件数组，满足任一 filter 即加入交换列表 |

**filter 每项参数：**

| 参数 | 类型 | 说明 | 示例 |
|:----|:----|:-----|:-----|
| `itemType` | int | 物品类型（5=Material, 7=Food, 4=Carrier, 6=CraftTool） | `{"itemType": 5}` |
| `minGrade` | int | 最低品级（含），0=9品, 9=1品 | `{"minGrade": 7}` |
| `maxGrade` | int | 最高品级（含） | `{"maxGrade": 1}` |
| `name` | string | 商品名模糊匹配 | `{"name": "香菇"}` |
| `amount` | int | 购买数量（不传则全量） | `{"amount": 2}` |
| `pricePercent` | int | 涨跌价（<0=降价，>0=涨价，0=原价） | `{"pricePercent": -1}` |
| `maxPrice` | int | 最高单价 | 预留 |
| `templateId` | int | 商品模板ID | 预留 |

**执行流程：**
1. 获取 ViewShop 上的 Exchange 对象和 GetTargetTradeableList()
2. 对每个商品读取 Key.ItemType、Key.TemplateId、Grade、Amount、Value、PricePercent
3. 用 filters 逐项匹配（filter 内 AND，filter 间 OR）
4. 对匹配商品调用 Exchange.SelectTargetItem(item, amount)
5. 调用 Refresh() 更新 UI

**响应示例：**
```json
{
    "requestId": "shop_001",
    "success": true,
    "data": {
        "success": true,
        "totalItems": 26,
        "added": 2,
        "skipped": 24,
        "items": [
            {
                "name": "香菇",
                "type": 5,
                "grade": 2,
                "amount": 2,
                "raw": "ItemDisplayData({Material, 香菇 (72), 34410, 0}, 2, 0/0)"
            }
        ]
    }
}
```

> **注意：** 此请求只将商品加入交换列表，后续仍需通过 `front_code` 点击 Confirm 完成交易。`Confirm` 按钮的 `interactable` 需为 `true` 才能交易成功。
