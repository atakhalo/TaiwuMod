# InGameHelper 技术架构

## 整体架构

```
外部程序 (AI Agent)
  │  写入 quest.json         读取 result.json (或 result_{id}.json)
  ▼                                                    ▲
┌────────────────────────────────────────────────────────────────┐
│  InGameHelperFrontend (Unity 前端, Assembly-CSharp)            │
│                                                                │
│  FileSystemWatcher:                                            │
│    ├─ quest.json         → 接收外部请求                        │
│    ├─ _backend_result.json  → 接收后端结果，转发到 result.json │
│                                                                │
│  请求处理:                                                     │
│    ├─ scene_hierarchy    → Unity API (主线程协程)              │
│    ├─ component_info     → Unity API (主线程协程)              │
│    ├─ component_field    → Unity API (主线程协程)              │
│    ├─ frontend_data      → SingletonObject.getInstance<T>()    │
│    └─ 其他              → 写入 _backend_quest.json 转发后端    │
│                                                                │
│  响应写入: result.json + 大结果自动拆分 (>1000B)               │
└───────────────────────┬────────────────────────────────────────┘
                        │ 文件通讯
                        ▼
┌────────────────────────────────────────────────────────────────┐
│  InGameHelperBackend (游戏后端, GameData)                      │
│                                                                │
│  FileSystemWatcher: _backend_quest.json → 处理 → 写结果        │
│                                                                │
│  BackendBridge.ProcessRequest()                                │
│    ├─ game_data        → 通用域查询 + 链式方法调用             │
│    ├─ taiwu_info       → 太吾基本信息                          │
│    ├─ character_info   → 角色全部字段                          │
│    ├─ character_name   → 角色姓名专用 API                      │
│    └─ world_info       → 世界日期信息                          │
│                                                                │
│  核心: DomainManager + Harmony Traverse + 反射                  │
│  技术: int→enum 转换, 泛型方法调用, 链式方法调用                │
└────────────────────────────────────────────────────────────────┘
```

## 请求路由

| 请求类型 | 处理方 | 方式 |
|:---------|:-------|:-----|
| `scene_hierarchy` | 前端 | 主线程协程 → Unity API |
| `component_info` | 前端 | 主线程协程 → Unity API |
| `component_field` | 前端 | 主线程协程 → Unity API |
| `frontend_data` | 前端 | 主线程协程 → `SingletonObject.getInstance<T>()` |
| `game_data` | 后端 | 写入 `_backend_quest.json` → 后端处理 |
| `taiwu_info` | 后端 | 同上 |
| `character_info` | 后端 | 同上 |
| `character_name` | 后端 | 同上 |
| `world_info` | 后端 | 同上 |
| 以上之外 | 后端 | 同上（默认转发） |

### 前端 (InGameHelperFrontend)

**插件入口**: `InGameHelperFrontendPlugin : TaiwuRemakePlugin`

#### 文件监听
- `quest.json` — 外部请求（Changed/Created 事件）
- `_backend_result.json` — 后端响应（Changed/Created 事件，转发到 `result.json`）
- 后台线程收到后通过 `_pendingLock` + `_pendingSceneJson` 传递到主线程

#### 主线程协程
- `SceneProcessRoutine()` — 每 0.2s 轮询 `_pendingSceneJson`
- 处理场景/前端请求后调用 `ProcessSceneRequest()`

#### 场景查询 (`SceneQueryService`)
- **`QueryHierarchy`**: `rootType="all_canvases"` → `FindObjectsOfType<Canvas>()`；`rootType="path"` → 按 `/` 分割路径逐级查找
- **`QueryComponentInfo`**: 定位 GameObject → 遍历 Component → Traverse 反射字段
- **`QueryComponentField`**: 定位组件 → 读取指定字段/属性
- 层级递归深度 5 层

#### 前端数据查询 (`GetSingletonData`)
- 通用实现：按类名搜索所有程序集 → `SingletonObject.getInstance<T>()` → **链式方法调用** → **读字段**
- 链式方法调用 (`ApplyFrontendMethodChain`):
  - `objectMethods`: 方法名数组（支持泛型语法 `Method<Type>`）
  - `objectArgsList`: 对应参数列表
  - 内部通过 Traverse + **反射**（`InvokeFrontendMethodReflection`）调用方法
  - 反射支持：泛型方法 `MakeGenericMethod`、int↔enum 转换、数字类型提升

#### 长结果拆分
- 响应 JSON 超过 1000 字符 → 写入独立 `result_{requestId}.json`，`result.json` 返回简要引用
- 索引文件 `result_index.json` 记录历史（最多 100 条）

---

### 后端 (InGameHelperBackend)

**插件入口**: `InGameHelperBackendPlugin : TaiwuRemakePlugin`

#### 文件监听
- `_backend_quest.json` — 前端转发的数据请求（Changed/Created 事件）
- `SafeWriteFile` 使用 `.tmp` 原子写入防止冲突

#### 请求处理 (`BackendBridge.ProcessRequest`)
- JSON 反序列化 → switch 分发到 `BackendDataService`

#### 数据查询 (`BackendDataService`)
- **`Query`** (game_data):
  1. `GetDomain(domainName)` → 从 `DomainManager` 获取域对象
  2. `InvokeDomainMethod` → 调用域方法（args 支持 `long→int` 转换）
  3. `ApplyObjectMethodChain` → 链式调用结果对象方法
  4. 读 `field` 或序列化整个结果
- **`QueryTaiwuInfo`**: `TaiwuDomain._taiwuCharId` + `GetCharacterBrief`
- **`QueryCharacterInfo`**: `Character.GetElement_Objects(charId)` → 深度 3 序列化
- **`QueryCharacterName`**: `CharacterDomain.GetNameRelatedData(charId).FullName` + `GetRealName` 互补
- **`QueryWorldInfo`**: `World.GetCurrDate()` + `_worldId` + `_isFinishedInit`

#### 链式方法调用 (`ApplyObjectMethodChain`)
- 执行流程: 域方法 → 结果对象方法(多级) → 读字段
- `InvokeObjectMethodDirect`:
  1. Traverse 按参数类型匹配
  2. 反射 `InvokeMethodWithEnumConversion`（int→enum 自动转换）
  3. `AccessTools.Method` 精确类型匹配
- 错误信息通过 `_lastInvokeError` 返回客户端

#### 域概览 (`GetDomainOverview`)
- 无 method/field 时，返回域对象的全部简单类型字段（移除了 `Take(30)` 限制）

## 通讯协议

### 文件接口

| 文件 | 方向 | 说明 |
|:-----|:-----|:-----|
| `quest.json` | 外部程序 → 前端 | 外部请求 |
| `result.json` | 前端 → 外部程序 | 外部响应（小结果直接, 大结果仅引用） |
| `result_{id}.json` | 前端 → 外部程序 | 大结果独立文件 |
| `result_index.json` | 前端 | 结果索引历史 |
| `_backend_quest.json` | 前端 → 后端 | 数据请求转发 |
| `_backend_result.json` | 后端 → 前端 | 数据响应 |

### 请求格式

```json
{
    "requestId": "唯一标识",
    "type": "请求类型",
    "params": {}
}
```

### 响应格式

```json
{
    "requestId": "对应请求标识",
    "success": true/false,
    "data": {},
    "error": null,
    "hasLongResult": false,
    "longResultFile": null
}
```

## 核心技术要点

### Harmony Traverse
- 前后端通过 `HarmonyLib.Traverse` 反射访问私有字段/方法
- 前端补充了 `UnityEngine` 类型（Vector2/3/4、Color、Quaternion、Rect）的特殊序列化

### 枚举类型转换
- 后端 `InvokeMethodWithEnumConversion`: 反射匹配方法签名，`int`→`Enum.ToObject()`
- 前端 `ConvertArgToParamType`: 类型逐级匹配（精确→枚举→数字提升）

### 泛型方法调用
- 前端 `InvokeFrontendMethodReflection`: 解析 `Method<T>(args)` 语法 → `FindTypeInAssemblies` 查找类型 → `MakeGenericMethod`
- 后端未显式支持泛型（通过 Traverse 的 `Method(name, args)` 处理）

### 大结果拆分
- 前端和后端都实现了长结果自动拆分（前端 1000B 阈值，后端也使用了此机制）
- 避免外部程序一次读取超大 JSON

## 配置 (config.xml)

```xml
<config>
    <workDir>forMod</workDir>              <!-- 工作目录（相对/绝对路径） -->
    <quest>quest.json</quest>              <!-- 外部请求文件 -->
    <result>result.json</result>           <!-- 外部响应文件 -->
    <resultIndex>result_index.json</resultIndex>  <!-- 结果索引 -->
    <backendQuest>_backend_quest.json</backendQuest>   <!-- 后端请求文件 -->
    <backendResult>_backend_result.json</backendResult> <!-- 后端结果文件 -->
</config>
```

> `workDir` 支持相对路径（相对于 mod 目录）和绝对路径。
